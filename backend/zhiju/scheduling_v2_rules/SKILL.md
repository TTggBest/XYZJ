# 智矩频道排期 v2：观众承接

目标是提高后续新片的推荐观看与订阅，而不是仅生成一张题材分高的日历。承接在发布前是假设，发布后才可用结果验证；不承诺每部爆款。适用于任意频道、语言与库存规模。

按系统提供的阶段和 JSON schema 执行；先读 [执行契约](references/execution-contract.md)。当前输入的频道、语言成片、已应用运营参考、原始剧情、历史、日期档位和证据快照是本次依据。只输出预览，不自行联网、回写数据库、改授权、上传或发布。

## 1. 从观众需求建立细分方向

先读本频道实际表现和已应用定位。把方向具体到：谁与谁冲突、谁主动行动、如何破局、观众经历什么情绪、最后得到什么回报。不能停在豪门、逆袭、总裁、打脸等宽标签；也不把细分等同于永久重复双胞胎、DNA等道具。

主、辅题材分别形成观看承诺。用 `hypothesis`、`supported`、`contradicted`、`insufficient` 标明证据状态。没有本频道数据时使用定位形成假设；一次峰值不是重复验证。不同语言、频道独立判断；可以共享剧情事实，不能照搬整套适配结论。

## 2. 覆盖完整库存，再比较

逐部读内容概要、剧情档案、剧情套路和核心人设，保留连续原文引用。所有候选均留下判断，包括未选作品；资料无法判断要明确缺口，不能消失在常用 Top 榜之外。

区分本频道的 `untested`（未发布）、`insufficient_exposure`（曝光不足）、`supported`（有支持）、`weak_with_evidence`（有较充分反证）、`packaging_issue`（有证据指向包装）和 `unknown`。状态必须说明实际来源，缺失不当作0；跨频道差异只能作线索，不替代本频道实测。比较同发布年龄、时长和来源条件；重叠窗口不能相加，最近未成熟数据不直接与成熟样本排名。

先判断持续主线是否兑现本次细分观看需求，再分相对层级；层级不是自造增长分数。优秀、未验证的强主题也可以优先。时长仅在适配与承接能力接近时用于取舍；不为了时长牺牲主题，不固定探索比例或剧目数。

## 3. 编排连续序列，不按单片榜单填日历

逐个日期档位比较剩余候选，与近期已发布证据、本次前档和同日另一档一起判断。每档写清：

- 本部独立吸引点击的真实冲突、情绪及结局回报；
- 为什么相同观看需求的观众还会想看这一部，具体情节怎样变化；
- 最接近的另一部候选是什么，为什么本档选当前这部。

逐档指定题材是硬约束；要求前期双档全强主题时，两档都应强化同一种细分观看需求。强匹配不足则留空并说明，不能用副题材或宽泛相关库存补位。用户明确选择辅题材时，也在该方向内选强匹配，不擅自修改其选择。

同频道沿用系统历史与本次去重。跨频道不以降低重复率为目标；真正适合可以同剧，不复制整套名单。播放列表按真实剧情和现有列表归档，不用列表相同证明承接，不为制造垂度误分列表。

## 4. 把包装、开场、语种成片分开核验

提出有原剧情依据的标题/封面承诺及开场待查点，不代替运营包生产。实际未读封面、开场、配音或正片时写“未核验”；语言成片清单只证明资源存在，不证明质量。现有自动链路没有媒体实物审阅，本版输出 `media_verification=unverified`，不能编造已看、已听或已兑现。

## 5. 给下一轮可执行反馈，不自动改已发布内容

结合上次承接假设与新表现，在 `next_actions` 说明应补哪项证据、下一轮检验什么：

- 有展示、点击弱但观看好：调查来源与包装；
- 点击好、开场早退：检查承诺兑现、开场和语种成片；
- 单片能看、后续没接住：比较观看需求、下一部入口和实际来源；
- 展示少或样本小：保留不确定性，不直接判题材失败或限流；
- 多频道同制作批次异常：核对共用制作/配音链路，不同时推翻全部定位。

这些是调查分支，不是凭单项指标断言因果。包装测试在账号和内容允许时使用 YouTube 原生 A/B；排期前后观察不能冒称随机实验。验收看后续多部新片的推荐观看、订阅及观看深度，不能用旧爆款、增加发布量或新增频道抬高总数。

沿用有效业务条件：明确不足30分钟不收；时长未知保留未知。最终合成与目标语言成片由系统筛选，到期在发布时间重查。《Tempting My Keeper》永久禁用。旧 v1、已发布修订和冻结工单保持原样。
