# XY Place

## Purpose

This step only does these things:

- generate the description
- generate the Chinese review translation of the description
- choose the best matching playlist
- provide the playlist URL

It does not search plot, does not generate titles, does not generate covers, and does not generate community image or community copy.
Workflow position:

- run this only when the user explicitly asks for description output
- this step must stay aligned with the same result groups from `xy-find`
- do not run `xy-merge` before this step is finished

## Inputs

Read:

01_频道数据.md
01_搜索资料.md
频道名_生成规范.md

If the current channel already has playlist information inside its generation brief or synced channel data, use that playlist information.

## Rules

- Before generating anything, check whether `01_频道数据.md` exists in the current package folder. If it does not exist, invoke `xy-data` first and create it.
- `频道名_生成规范.md` is a channel-level dependency. It must come from the corresponding channel folder and is not generated by this workflow.
- Generate the description from the plot summary and the current channel generation brief.
- Open with one concrete conflict, abnormal situation, identity mismatch, or relationship anomaly. Use only the strongest click entry and do not summarize the whole drama. Do not stack several betrayals, props, or consequences into the opening sentence; move secondary facts into the minimum background only when needed.
- Continue in two to four natural paragraphs whose length, order, and transitions follow the current plot and target language rather than a fixed template. Include only the relationship and background needed to understand the conflict.
- Use exactly one concrete mid-story event as the escalation. State who acted, what specific anomaly appeared, and whose judgment, relationship, or position changed directly because of it. Do not stack a second independent escalation event.
- Do not use the final identity reveal, final parentage confirmation, villain's final punishment, final reunion, proposal, wedding, inheritance result, or other ending climax as the escalation. Leave at most one plot-specific unresolved question or a non-question suspense statement. Name the relevant character instead of using a vague stranger, woman, man, mother, or person when the verified name is available and clearer.
- Before drafting, choose one precise current-drama `editorial_anchor`. Use `editorial_anchor` as the sole sentence-selection center: every background sentence must be necessary to understand it, and delete a sentence when removing it does not reduce understanding of that anchor. The final suspense must directly close the loop with the opening misunderstanding or follow the immediate unresolved consequence of the selected escalation; it must not open a new abstract question or switch to another plot line.
- Before returning JSON, silently reread and rewrite the body inside this same model call. Keep one spelling for each person, preserve narrator-versus-character knowledge, keep causes before effects, replace translated source-language logic with native target-language collocation, and make the final sentence understandable on its first reading. This is internal single-call editing, not a second model call or a semantic Validator.
- Add SEO information only when the target-language version, Chinese-drama identity, or one or two essential genre terms are not already clear, and integrate it naturally into an existing paragraph. Never place a blunt standalone genre declaration after the suspense, use a fixed "if you like A/B/C, watch to the end" sentence, or output a keyword list.
- Before finalizing, remove generic AI phrases, repeated facts, report-like headings, plot-highlight lists, story-type lists, mechanical timelines, and any sentence whose deletion would not reduce comprehension or suspense. Do not expand the title line by line into a synopsis.
- This remains a free-body generation and self-check preference, not a new Validator rule.
- When `creative_history` is supplied, use its same-drama descriptions only as negative references. Select a different opening premise, emotional emphasis, reveal order, and payoff framing; never translate or paraphrase another channel's description.
- Treat the title `packaging_brief` as binding. Return its exact `creative_slot_id` as `packaging_brief_id`, and copy its `channel_direction` and `core_story_promise` exactly; the controller rejects any drift before writeback.
- Before writing the description, output machine fields `opening_hook_type`, `payoff_hook_type`, and `editorial_anchor`. Hook types use the same allowed A/B taxonomies as `xy-title`; `editorial_anchor` is a concrete Chinese phrase naming this package's unique editorial entry point.
- The description must follow the current channel style and recommendation direction.
- The description must match the current drama itself and must not become a generic reusable template.
- When minors appear, keep adult wrongdoing and child-safe facts in separate sentences. Do not describe a minor as the direct target of abandonment, humiliation, hostile surveillance, coercive parenting, police restraint/control, adult confrontation, or bedroom/bedside intimacy. Preserve the adult betrayal, reversal, punishment, and payoff; keep the child as a protected relationship, identity, reunion, or family anchor. Do not omit verified children or soften the main hook.
- If plot summary is available, use plot summary first.
- If plot summary is weak, use the Chinese drama name or alias together with the current channel generation brief.
- Choose the best matching playlist for this drama from the current channel's available playlists.
- Keep that best match in the structured `playlist` and `url` fields, but the public description must list every playlist registered for the current channel. Show the best match first, then every remaining exact playlist name and viewer-facing URL. Never omit a registered playlist.
- Do not invent playlist names.
- Do not invent playlist URLs.
- If the channel has no perfect playlist, choose the closest existing playlist.
- Never provide a playlist recommendation reason, plot-match explanation, SEO explanation, playlist summary, or any sentence after a playlist URL. The controller rebuilds the public playlist block deterministically from the selected registered playlist and the registered channel order.
- The Chinese `translation` and `channel_theme_phrase_translation` fields are review aids only. Make them useful when practical, but their presence, wording, punctuation, theme keywords, and similarity do not decide acceptance or retry.
- Production acceptance is based on the target-language public description and its real assets. Do not use a Chinese review translation as semantic proof for the public description.
- V14 fixed description assets and the channel Hashtag contract are frozen by the controller from `/Volumes/TTggg_mini01_2T/CodexData/.codex/skills/xy-place-v14/rules/description_rules.json` and `/Volumes/TTggg_mini01_2T/CodexData/.codex/skills/xy-place-v14/rules/channel_hashtag_whitelists.json`; do not search legacy directories or accept channel-folder overrides.
- Use the exact current channel as the only Hashtag routing key. Do not route by language and do not borrow from another channel, even when both channels use the same language.
- Output exactly 12 hashtags. Place `#cdrama` exactly once at position 3. Select the other exactly 11 tags from `channel_hashtag_whitelist.additional_candidates`; `#ChineseDrama` and `#ShortDrama` are not mandatory.
- Within the exact current-channel whitelist, use target-market audience-entry candidates first, then channel-history candidates, then current-drama-specific candidates, and finally cross-market generic candidates. This is a soft supply and selection priority, not a fixed quota: current-drama relevance still decides which exact 9 tags are selected, and no tier has a required count. Hashtags improve metadata fit; do not treat one hashtag as an independent cause of recommendation traffic.
- First remove candidates that do not fit the current drama. At least one of positions 1 and 2 must come from `channel_hashtag_whitelist.target_language_tags`. Target-language qualification is owned only by this pre-registered exact-channel asset; the model must not infer that an unregistered mixed, transliterated, English, or other tag qualifies. Never sacrifice current-drama relevance elsewhere or impose category quotas. This is a generation structure rule and model self-check, not a new Schema field or a general semantic scoring gate.
- Cross-market generic tags are fallback coverage and must not dominate when eligible market-, channel-, or drama-specific candidates fit the current drama.
- Hashtags are final YouTube plain text, not Markdown source. Copy each selected hashtag character-for-character from the whitelist. Never add a backslash before `_` or any other hashtag character: write `#دراما_صينية`, never `#دراما\_صينية`.
- Never invent, translate, concatenate, respell, change case, or otherwise modify a tag. When the exact channel whitelist is missing or insufficient, fail before the model call rather than falling back to a language pool or generated tags.
- The final result must stay focused on:
  - description
  - playlist
  - translation
- Run a self-check before finalizing.
- For registered languages that do not use Han characters, no Chinese characters are allowed anywhere in the public description. The hashtag line is exempt because its non-mandatory tags have no language or script restriction. Japanese keeps its legitimate kanji.
- The controller appends only the registered fixed combined subscribe-and-share CTA line and disclaimer lines. The combined CTA uses `🔔` for subscription guidance and `🙏` for share guidance. Legacy welcome copy, channel introductions, and generic comment questions are not public output.
- End immediately after the fixed disclaimer. Never output `==中文剧名==`, a Chinese drama name, internal ID, review note, score, generation note, or Validator result.

## Description Template

Use this production structure. The model writes the natural free body and selects hashtags and the primary playlist; the controller owns the playlist block and compact fixed footer:

```text
🔥 [one concrete conflict, abnormal situation, identity mismatch, or relationship anomaly; only one strongest click entry]

[two to four natural paragraphs: only necessary relationship/background, one concrete mid-story escalation, and at most one non-spoiler suspense point]

[optional: one natural SEO sentence only when essential target-language, Chinese-drama, or one-to-two genre terms are not already clear]

[registered target-language tag] [exact eligible current-channel tag] #cdrama [nine further exact eligible current-channel tags]

👇 [Translate the playlist introduction into the current channel language]:
[playlist name in channel language] 👉
[playlist link]

📌 [Translate “More great playlists” into the current channel language]:
1. [playlist name in channel language] 👉
[playlist link]

2. [playlist name in channel language] 👉
[playlist link]

3. [playlist name in channel language] 👉
[playlist link]

[If there are more playlists, continue with 4, 5, 6... until all remaining playlists of the current channel are listed.]

🔔 [controller outputs the exact registered combined subscribe-and-share CTA]

⚠️ [controller outputs the exact registered authorization, professional translation/dubbing, and fiction disclaimer]
```
