# XY Post

## Purpose

This step only does these things:

- generate the 1:1 community image prompt
- generate the community post copy
- generate the Chinese review translation of the community copy

It does not search plot, does not generate titles, does not generate covers, and does not generate description/playlist copy.
Workflow position:

- run this only when the user explicitly asks for community output
- this step must stay aligned with the same result groups from `xy-find`
- after `xy-post` is finished, run `xy-merge` only when the user explicitly sends `合并`

Read:

01_频道数据.md

频道名_生成规范.md

## Rules

- When `creative_history` is supplied, same-drama community packages are forbidden references: do not translate, paraphrase, or reuse their post hook, interaction question, selected moment, image scene, action, or evidence prop.
- A different target language does not make a repeated community concept independent.
- Before writing community content, output machine fields `community_hook_type`, `selected_moment`, and `interaction_angle`. The hook type uses the title A/B taxonomy; the other two fields are concrete Chinese review phrases used for cross-channel collision checks.
- Every community result must return the title `packaging_brief.creative_slot_id` as `packaging_brief_id`, and copy `channel_direction` and `core_story_promise` exactly; the controller rejects any drift before writeback.

- Before generating anything, check whether `01_频道数据.md` exists in the current package folder. If it does not exist, invoke `xy-data` first and create it.
- `频道名_生成规范.md` is a channel-level dependency. It must come from the corresponding channel folder and is not generated by this workflow.
- For future V2 tasks, output exactly `community_count` independently authored community-result blocks with sequential `plan_index`; zero means skip. Legacy tasks keep their original boolean behavior.
- Every block must use a different selected moment, interaction angle, scene family, main action, key prop, composition, palette, copy, and image concept.
- Use the supplied video link exactly once in each copy. If unavailable, use the exact placeholder `【视频链接待补】` once; do not treat that fixed placeholder as prohibited mixed Chinese copy.
- Do not force exactly 3 blocks.
- If there is 1 search result, output 1 block.
- If there are 2 search results, output 2 blocks.
- If there are 3 search results, output 3 blocks.
- The community workflow order is fixed:
  `unique conflict / uncertainty boundary from 01_搜索资料.md -> title direction from 04_标题方案.md -> current channel brief tone -> community image / community copy`
- Do not start from a generic reusable community template.
- The community image is always `1:1`.
- The actual community image prompt must be written in English.
- Scene, characters, action, conflict, composition, lighting, style, safety, and visual layout inside the image prompt must all be described in English.
- Do not write Chinese scene descriptions inside `社群图 1：1`.
- Only visible overlay text, hook sentence, subscribe CTA, and share CTA may use the channel language.
- Chinese is allowed only inside `社群文案翻译` or review labels outside the actual prompt/copy body.
- The community copy must use the channel language.
- The community copy body must be pure channel language. Do not leave Chinese names, Chinese tags, copied Chinese notes, or mixed Chinese sentences inside the final copy body.
- The image must show a strong reversal, direct emotion, and a visually readable conflict moment.
- Use only the drama's original `source_language` for all visible adults and children: `zh` means Chinese facial features and a Chinese short-drama cast; `en` means European and North American facial features and a Western short-drama cast.
- Missing or unavailable original language defaults to Chinese faces. Never determine faces from channel language, dubbing language, title language, or filename.
- Match both the current channel language and the current channel's winning identity model.
- Treat the fixed channel theme as existing context that guides angle selection and expression. Do not force its wording to appear verbatim in the public copy or image hook, and do not create a new planning or output field for this purpose.
- If the current channel already has a stable high-performing structure in its report or synced brief, keep that recognizable structure when the current plot supports it.
- Do not drift into generic cross-channel copy.
- Do not import another channel's winner structure into this channel.
- Avoid generic slogans.
- Avoid claims that are not supported by the story card.
- The community image hook and community copy hook must be specific to this drama, not just to its genre.
- The image hook must express only the selected scene's single core conflict, choice, or relationship change. It must not also carry a complete plot summary or the interaction question; keep the full interaction question in the Community copy.
- Build each Community copy around one primary audience decision. Include only the minimum background needed to understand that decision, then stop explaining the plot. Do not introduce a second competing interaction goal.
- The Community body before the formal interaction CTA must establish only scene, conflict, and choice background; it must not ask the audience any question. Put the one audience-facing question only in the formal `🤔` interaction CTA.
- This is a generation priority, not a question-mark count, word limit, character limit, or Validator rule. Natural supporting suspense statements are allowed when they serve the same decision.
- Same channel plus same genre is not enough reason to reuse the same `they had no idea / whole family shocked / subscribe and share` skeleton with only a few nouns changed.
- No gore, no sexual content, and no unsafe child/teen depiction.
- If the channel report or synced channel data provides `专属表情`, the final subscribe line must use that emoji. Do not replace it freely.
- The community-image bottom CTA is a channel-level fixed asset, not a drama-level variable.
- The Community-copy first-line full-video CTA is also a channel-level fixed asset. Only the video URL changes by drama.
- Keep the channel-language hook sentence, both CTA buttons, emoji, and their exact fixed layout inside the generated image prompt. Do not switch to a text-free image or a later code-overlay workflow.
- For the same channel, the subscribe CTA text, share CTA text, icon order, layout style, and footer style must stay identical across all community images.
- Do not rewrite the bottom CTA just because the drama changes.
- Reuse `full_video_cta`, `subscribe_cta`, `share_cta`, and `layout_style` from the controller-provided `community_footer_cta` exactly as stored.
- Do not rewrite, shorten, decorate, or synonym-swap those values.
- If the read-only channel folder has no CTA file, use the controller-resolved values from the batch-frozen community contract. Never create or update files in the historical channel root.
- The default preferred footer layout is a simple dual-pill layout: left `🔔 subscribe`, right `🙏 share`.
- Same language is not enough. The stronger rule is: same channel means same footer CTA copy and same footer CTA layout.
- Same channel does not mean the main hook sentence, conflict phrasing, reversal paragraph, interaction question, or image scene should be the same.
- You must pull at least one drama-specific concrete hook from `01_搜索资料.md`, such as `hearing the child's thoughts`, `lucky gratitude baby`, `kung fu twins`, `saved the Huo family child`, `mistaken savior`, `termination agreement`, or `rich-family favor war`.
- If the community copy could fit another drama on the same channel by changing only 1 to 3 nouns, reject and rewrite it.
- Same-channel differentiation and same-channel recognizability must coexist.
- For mature channels, the community body should usually contain both:
  - one channel-level stable anchor from the current channel report, when the plot supports it
  - one drama-specific unique hook
- Do not let every post become identical, but do not erase the channel's core identity tag either.
- If `01_搜索资料.md` lists something under `不可确认 / cannot be treated as fact`, do not use it in the community image or the community copy.
- If `01_搜索资料.md` does not provide confirmed plot and only gives a name-based synopsis from the Chinese title or aliases, then the community hook may only be built from the literal title conflict and the selected title direction.
- Do not invent unverified relationship reversals, specific locations, files, children, weddings, hospitals, or identity props.
- The community image must not be a square remake of the cover.
- It may use the same story hook, but it should choose a different conflict moment, reaction angle, or question angle.
- Before writing the community image prompt, compare it against the current package's `04_封面提示词.md`.
- The community image must differ from every cover on the following community concept tuple:
  - scene family
  - primary visible action
  - evidence / object
  - emotional question
  - foreground obstruction
- If the square image looks like a cropped cover, reject and rewrite it.
- The community image is a feed hook, not a fourth cover.
- It should answer a viewer-facing question or emotional reversal that makes the user want to click the video link.
- When supported by the plot, prefer one of these community-native angles:
  - before-recognition or after-recognition moment
  - warm family payoff after the truth
  - one decisive object on a table while adults react around it
  - one public misunderstanding frozen at the turning point
  - the female lead's emotional choice instead of a generic `everyone is shocked`
  - the villain or fake identity losing control while the real family stands together
- Do not reuse one default cross-drama template like `office desk + evidence + shocked CEO`, `luxury room + document + whole family shock`, or `child pointing at adult`.
- If one of those generic skeletons becomes the main structure, the output is invalid.
- For community images involving children, apply the same child-safety visual rules as `xy-cover`.
- Do not show children accusing adults, pointing at adults, exposing evidence as the main reveal, appearing in medical emergency scenes, or being described with rescue/save/weak/pale/clinic/hospital/doctor-rushing/blood/violence/revenge/panic/frightened language.
- Children should function as warm emotional anchors, not prosecutors.
- For child-centered stories such as baby, twins, triplets, four kids, five kids, multi-kids, or any explicit child-count hook, keep that count as a first-level story signal whenever the title/search evidence uses it as a hook.
- Prefer reducing adult count before reducing child count.
- Do not collapse `twins / triplets / four kids / five kids` into `one child plus implication`.
- In child-count stories, the visible children must directly carry the hook.
- Do not replace the required visible children with symbolic stand-ins such as drawings, photo frames, handprints, school bags, baby shoes, toys, strollers, silhouettes, or off-screen mention.
- For child-led community images, the default adult count is `1-2` key adults while preserving the necessary visible children.
- If the frame feels crowded, remove adults first, then side characters, then props. Do not solve the crowding problem by deleting the children that define the hook.

## Community Image Template

The community image must use one concise hook sentence, not just a few core words.

Use this structure under `社群图 1：1：`:

```text
Create a square 1:1 YouTube Community post image for a short drama.

Scene:
[Describe one strong reversal or conflict moment from the story in English.]
- Unless the source story has only one confirmed location, this scene must be materially different from the 3 cover scenes.

Main characters:
[Describe the main people, identity relationship, expression, and action in English.]
- Explicitly state the facial features and cast appearance selected by the controller's source-language cast requirement; apply it to all visible adults and children.

Conflict:
[Describe the visible conflict in English: humiliation, betrayal, hidden identity reveal, revenge, CEO shock, family shock, comeback, or sweet reversal.]
- For child-led stories, write the conflict as family recognition, emotional reunion, or adult realization.
- Do not make children accuse, expose, command, or point at adults.
- If the title/search evidence explicitly says twins, triplets, four kids, five kids, or another exact child count, keep that count visible whenever possible.

Composition:
- 1:1 square image
- medium close-up or half-body characters
- main faces must be large, sharp, and unobstructed
- strong emotional contrast
- clear foreground subject
- background supports the story but must not be messy
- no tiny full-body distant characters

Hook sentence overlay:
[One concise channel-language hook sentence expressing the scene's core conflict, choice, or relationship change.]
- big, bold, readable
- high contrast
- thick outline
- subtle shadow
- must be eye-catching on mobile
- must not cover the main characters' faces

Bottom CTA overlay:
🔔 [channel-language subscribe CTA]   🙏 [channel-language share CTA]
- If `community_footer_cta.json` exists, use its fixed CTA copy exactly.
- Use the same layout every time for the same channel.
- Default preferred layout: two separate rounded black pills with yellow outline, left subscribe, right share.
- Place the whole bottom CTA block slightly higher than before.
- Do not stick it to the bottom edge.
- Keep the CTA block bottom edge roughly 6% to 9% above the image bottom edge.
- Keep a clearly safer bottom margin than the old workflow.
- Must not cover faces or important story objects.
- Must be readable and high contrast.
- Keep the CTA block horizontally centered and visually balanced.

Visual style:
- natural live-action TV drama still
- realistic lens rendering and natural skin texture
- ordinary clothing wrinkles and believable location lighting
- slightly softer environmental detail while faces remain readable through framing
- dramatic but photographic, without plastic beauty-filter rendering
- do not request ultra sharp focus, crisp facial details, high/strong micro-contrast, clean edges, sharp facial highlights, or mobile-readability rendering

Safety:
- no gore
- no sexual content
- no unsafe depiction of children or teenagers
- no real celebrity likeness
- no graphic violence

Goal:
Make viewers stop scrolling, click the video link, comment, subscribe, and share.
```

## Community Copy Template

Use this flexible structure under `社群文案：`.
The first line with the video link, and the final subscribe/share lines, are fixed-structure lines.
The body itself must stay specific to this drama and may adapt to the story rhythm.

```text
🔥 {full_video_cta} 👉 https://youtu.be/VIDEO_ID
[1-2 short lines: strongest conflict / humiliation / misunderstanding / betrayal]

[turn sentence: use this drama's own reversal, do not default to "but they didn't know"]

[1-2 short lines: identity / power / secret / reversal explosive point]

[1-2 short lines: result / whole family shock / CEO silent / enemy regret]

🤔 [interaction question: if it were you, what would you do? who would you believe?]
👇 [comment invitation: tell us in the comments]

[subscribe CTA] 🔔[channel-exclusive emoji]
[share CTA] 🙏
```

Copy rules:

- The first line must contain exactly one visible short URL:
  `https://youtu.be/VIDEO_ID`
- The first line must exactly equal `🔥 {full_video_cta} 👉 {video_link}` from the controller-provided channel CTA object. Do not paraphrase it.
- Do not use Markdown links anywhere in community copy.
- Double-link syntax, square-bracket links, or `[short-link](long-link)` are all invalid.
- This is a hard rule across all channels and all export targets.
- Community copy may only contain the bare short link, never `[https://youtu.be/VIDEO_ID](https://youtu.be/VIDEO_ID)` or any other Markdown-wrapped URL.
- For fixed emoji, minimum non-empty line count, URL format, and other script-side validations, read `rules/community_copy_rules.json` relative to this `SKILL.md`.
- Do not maintain a second hardcoded validator elsewhere.
- For the Bengali channel `আমার প্রেম的故事`, the first line must be exactly:
  `🔥 সম্পূর্ণ গল্প দেখতে এখানে ক্লিক করুন 👉 https://youtu.be/VIDEO_ID`
- Do not insert a blank line between the video-link line and the first conflict line.
- Keep lines short for mobile reading.
- `🔥`, `👉`, `🤔`, `👇`, `🔔`, and `🙏` are fixed structural emojis.
- Add channel-exclusive or emotional emojis only when they strengthen the result.
- The final subscribe line should follow the channel's locked style when applicable.
- The final share line should also follow the channel's locked style when applicable.
- The above fixed-line examples are structure references. The exact final wording must still match the current channel data and current channel brief.
- The first visible screen should contain both the video link and the strongest conflict.
- For channels with a locked winner model, the first 3 to 4 non-empty lines should usually expose at least one stable channel anchor whenever the current plot supports it.
- Use only this channel's own anchor, never another channel's high-frequency opening mode.
- The community copy must create curiosity, argument, empathy, or a forced choice.
- Keep one primary audience decision throughout the copy. Supply only the minimum background needed to understand that decision instead of retelling the Description, and do not introduce a second competing interaction goal.
- Before the formal `🤔` interaction CTA, write only scene, conflict, reversal, payoff, or choice background; do not ask the audience a preliminary or rhetorical question. The formal `🤔` line owns the only audience-facing question.
- The interaction question must be tied to this drama's own reversal.
- Do not repeatedly ask generic questions such as `who would you believe` or `what would you do` unless the story's actual conflict makes that exact question specific.
- Prefer a three-part logic:
  - part 1: this drama's unique conflict
  - part 2: this drama's unique reversal
  - part 3: this drama's unique payoff or emotional choice
- Unless the source story card itself truly works that way, do not default to the generic rhythm `she was humiliated -> they didn't know -> whole family shocked`.
- If two adjacent packages end up using the same body rhythm, same question, and same image scene with only names or one prop changed, reject and rewrite.
- `社群文案翻译` is a review aid only. Provide it when practical, but its
  presence, wording, punctuation, theme keywords, and similarity do not decide
  acceptance, retry, or collision of valid public Community copy.

## Community Copy Acceptance Tests

Before writing files, reject and rewrite if the community copy matches any of these:

- it uses Markdown link syntax such as `[text](https://...)` or `[https://...](https://...)`
- it does not contain exactly one visible `https://youtu.be/VIDEO_ID`
- the first line does not contain `🔥`, `👉`, and a single bare short link together
- there is a blank line between the video-link line and the first conflict/reversal line
- it has fewer than 8 non-empty lines
- any Chinese characters appear anywhere inside the community copy body
- it only contains CTA and a question, without a complete three-part story body: conflict, reversal, payoff / emotional choice
- any fixed structural emoji is missing: `🔥`, `👉`, `🤔`, `👇`, `🔔`, `🙏`
- the final two lines do not include a subscribe line with `🔔` and a share line with `🙏`
- the body can fit another drama on the same channel by changing only a name, child count, or one prop

## Community Image Acceptance Tests

Before writing files, reject and rewrite if the community image prompt matches any of these:

- the actual image prompt contains Chinese descriptions instead of English descriptions
- it shares both the same scene family and the same main action with any cover from `04_封面提示词.md`
- it uses a generic skeleton such as `office desk + evidence + shocked CEO`, `luxury room + document + family shock`, or `child points at adult` without a drama-specific reason
- it uses only a few keywords instead of a full hook-sentence overlay
- a child appears as accuser, judge, evidence-holder, phone recorder, or finger-pointing reveal figure
- a child-related prompt contains rescue/save/weak/pale/clinic/hospital/doctor-rushing/blood/violence/revenge/panic/frightened wording, even in negative form
- a child-count story such as twins, triplets, four kids, five kids, or baby hook is visually collapsed into one child without source evidence that the scene truly contains only one child
- a child-count story tries to replace missing visible children with symbolic stand-ins such as drawings, photo frames, handprints, school bags, toys, or silhouettes
- when `community_footer_cta.json` exists, the bottom CTA covers faces, sits too close to the bottom edge, or modifies the fixed channel CTA copy/layout
