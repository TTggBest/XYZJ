# V14 本机执行器

这是新增执行通道。原飞书同步、手动录入及运营包操作全部保留；本机执行器不会读写飞书，也不会继续旧本地批次。

## 配置

先由管理员在智矩 V14 设置绑定已登记的本机设备 ID、Codex 账号配置名（首期 current）和明确模型。上传固定规则 JSON 和频道材料。模型候选是配置值，不代表账号已获得权限；实际调用不支持时明确报错，不回退模型。

固定规则可在项目目录运行 `PYTHONPATH=backend .venv/bin/python -m zhiju.v14_executor --export-rules` 导出到标准输出；内容来自项目内固定 V14 资源，不改原 Skills。将输出保存为 JSON 后在设置页面上传。

频道材料按智矩频道内部 ID 提供对象，每个对象包含 language、gender、direction、generation_spec、description_fixed_assets、community_footer_cta，以及 playlists（name/url 列表）。community_footer_cta 保留 full_video_cta、subscribe_cta、share_cta、layout_style。说明阶段还需当前频道自己的 channel_hashtag_whitelist，包含 mandatory_hashtags、selection_count、additional_candidates、target_language_tags，不能借用其他频道。generation_spec 保持现有 V14 的 GLOBAL、TITLE、COVER、DESCRIPTION、HASHTAG、COMMUNITY、PLAYLIST 七个标题段。材料缺失会阻止模型调用。

先登记并启用执行主机，在当前公司 V14 设置中选择其设备 ID。保存设置后，由已登录的公司管理员点击“授权本机执行并下载配置”，下载一个使用现有认证体系、固定当前用户/公司/执行主机的短期会话，最长不超过当前网页登录会话的剩余有效期。AI 执行授权不依赖账号中心的“客户登录设备绑定”，不会创建或修改该绑定，也不会切换浏览器当前账号。

在本机工作区之外保存下载的配置 JSON（限制为本机用户可读，绝不提交到 Git）：

```json
{
  "base_url": "https://你的智矩地址",
  "tenant_id": "当前公司内部ID",
  "host_id": "已登记设备ID",
  "account_profile": "current",
  "session_token": "操作者授权的智矩登录会话",
  "codex_binary": "/本机/codex/绝对路径",
  "timeout": 900
}
```

Codex 使用当前 CLI 账号；可用可选 codex_home 指定本机凭据位置，但不上传凭据。智矩会话要绑定同一设备。未登记设备、租约/会话过期或切换公司时停止领取，重新登录后再启动。不要在聊天中粘贴会话令牌。

## 启动与停止

正常使用不需要手动开执行器。绑定的 Mac 一次性安装本机唤起组件后，“开始生产选中”“一键开始待生产”、单条开始、详情重试唤起和继续运行都会自动检查本机授权与 Codex 登录，再启动执行器。队列处理完后执行器和 Codex 子进程退出；只有不运行模型、不轮询业务队列的轻量 loopback 唤起服务保留，由当前用户 launchd 自动管理。

执行器默认使用 10 个普通 Python Worker（线程池），每个 Worker 同时只处理一条工单，并拥有独立的云端客户端和 Codex 内容调用。一个主管进程不代表只有一条工单并发；模型内容调用最多同时 10 个。旧的待回传缓存先由主管串行回传，再并发领取，各工单使用独立运行目录，不能重复回传或领取。`--workers 1` 可显式限制为单 Worker，`--once` 仍仅处理一条。真实授权失效时停止全池并保留待回传结果，重新登录授权后先回传，不重生成已产生的结果。

执行授权仍不超过当前网页登录会话期限。授权剩余不足 960 秒（一次最长 900 秒模型调用及回传余量）时，开始前明确要求重新登录，不启动模型；此检查不保证整个批次能在授权期限内完成，也不会自动延长权限。0 套社群在严格 Schema 校验后接受空结果，不调用模型。历史上由 `results_missing` 误判的零社群任务，仅在明确确认旧进程停止后允许通过恢复接口继续，保留全部已接受结果与旧错误记录；真实内容重试耗尽仍须人工审核。

安装须获用户授权，并从已提交推送的 dev 版本进行。使用已装好运行依赖的 Python：

```bash
python scripts/install_v14_launcher.py --origin https://你的智矩地址 \
  --tenant-id 当前公司ID --host-id 已绑定主机ID --codex-binary /本机/codex/绝对路径
```

组件仅监听 `127.0.0.1:19733`，只接受安装时指定的智矩网页来源、公司、主机和账号配置；不接受远程 shell 或浏览器指定的执行路径。网页登录短期授权通过私有 stdin 传给本次子进程，不保存在配置文件、URL 或日志里。浏览器首次询问本地网络访问权限时需要允许。在其他机器访问云端页面不能通过此组件唤起绑定 Mac。

组件不存在、Codex 未登录、授权过期或绑定不一致时，预检失败，不创建新的生产任务。排队后若唤起失败，页面明确报错，可在工单详情“重试唤起执行器”；不会重复创建工单。退出码异常保存在本机 `/health` 状态中，日志位于 `~/Library/Application Support/zhiju-v14-launcher/worker.log`。

手工诊断仍可执行 `PYTHONPATH=backend .venv/bin/python -m zhiju.v14_executor --config /绝对路径/executor.json --once`，只领取一条；`--drain` 处理完队列后退出。去掉两者则持续领取，仅作为显式手工运维方式，正常网页操作不依赖此方式。

Ctrl-C/停止 LaunchAgent 后，先确认 Codex 子进程已退出，再在智矩点击继续并明确确认旧进程已停止。失联超过 90 秒仅显示中断，不自动把工作交给另一主机。

输出成功但回传断网时，结果保存在当前用户缓存的公司/主机/运行目录；下一次启动先重传该结果，不重新生成。若操作者已明确取消或继续、使旧领取失效，执行器回读云端确认后将旧缓存保留为 abandoned.json，不再阻塞新领取；其他回传冲突仍报错。不要手动删除 pending.json 来跳过回传。缓存不是业务权威，恢复仍从云端已接受结果开始。

## 社群数量调整与补产

排期与工单列表的“社群”列均提供“调整社群”。生产前可设 0–20 套；每套包含频道语言文案、中文审阅对照和 1:1 图片提示词。飞书排期按页面统一的北京时间整日计算默认数量：单更每条 2 套，双更每条 1 套，不能按频道当地日期拆散双更。未人工确认的飞书默认数量（包括旧 0），会在创建工单、或尚未生产的 V14 工单冻结输入前按同一规则校准；重新同步只校准尚无工单且未人工调整的排期；手动通过“调整社群”明确保存的 0 不会被覆盖（包括确认保留原 0）。已有 V14 运行快照及已完成结果不自动修改，需走补产入口。

已完成且未审核的零社群 V14 工单，可从同一入口增加社群数量并自动唤起本机补产。服务端只为社群与合成新增生产轮次，保留原工单、运营包、历史尝试及搜索/标题/封面/说明结果；旧空社群和旧合成记录保留，但不再作为本轮完成依据。运行中、已有社群内容或已审核运营包拒绝覆盖。此操作不生成图片、不发布、不写飞书。

## 完成边界

模型读取云端快照，当前工单按六节点运行；每次内容失败最多初次加两次修复，系统错误另计。文本完成显示 text_ready，现有运营包进入 review_pending 等待审核，不代表图片已生成或最终交付。

首次真实验收需要明确选择一个未生产的测试工单和模型，再授权启动。不自动安装、不自动发布 YouTube、不自动写飞书。
