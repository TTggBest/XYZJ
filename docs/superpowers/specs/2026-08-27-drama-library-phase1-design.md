# 智矩剧库第一阶段设计

日期：2026-08-27

## 目标

把当前只有简单列表的本地剧库扩展为可维护、可同步、可检索的剧目主数据中心。本阶段只处理剧库主档、语言覆盖展示和频道发布分布，不接入智核制剧进度，也不把制剧进度错误拆成“剧目 + 语言”。

## 当前事实

- 飞书 Wiki：`TzkWwanAAikv7pkOJcTcddiVnoh`。
- 飞书当前“剧库表”实际 Sheet ID 为 `b8b567`，共有 327 条数据；用户提供链接中的 `OHTcqg` 当前实际对应“语言”页。
- “剧库表”字段为：作品名称、百度网盘链接、内容概述、剧情档案、剧情套路、核心人设、到期时间、批次、状态。
- 飞书状态现有值为：制作 188 条、空白 109 条、已删 30 条。
- 开发 MySQL 当前有 49 部剧、0 条语言定义、0 条剧目语言记录、20 条已经关联剧目的 YouTube 视频。
- 系统已经有 `dramas`、`drama_aliases`、`drama_core_terms`、`languages`、`drama_translations` 和 `youtube_videos.drama_id`，本阶段在这些既有边界上扩展。

## 权威与同步规则

MySQL 是智矩的业务事实来源。飞书在过渡阶段是剧库导入字段的上游来源，点击同步时执行单向增量导入：

1. 每次同步先按 Sheet 标题解析“剧库表”的实时 Sheet ID，不把 `b8b567` 写死。
2. 以规范化后的“作品名称”匹配 `dramas.normalized_title`，不使用模糊匹配，不通过别名自动合并不同主档。
3. 不存在则新增；存在则逐字段比较并更新变化字段；完全一致才计为跳过。
4. 飞书状态“制作”或空白映射为 `active`，“已删”映射为 `archived`。
5. 飞书“到期时间”按北京时间自然日解释，只有日期时落库为当天 `23:59:59`；空值保持为空。
6. 飞书同步不物理删除剧目。归档剧目保留历史运营包、排期和 YouTube 视频关系。
7. 飞书管理的九个字段在再次同步时可以覆盖智矩中的对应字段。页面需要明确标记数据来源和最后同步行号，避免把临时手工修改误认为不会被覆盖。
8. 同步失败按整次事务回滚，并记录 `FeishuSyncRun`；不产生半批成功数据。

## 数据模型

### 扩展 `dramas`

新增字段：

- `batch_name`：飞书“批次”。
- `source_type`：`manual` 或 `feishu`。
- `source_sheet_id`：本次解析到的剧库 Sheet ID。
- `source_row_number`：飞书原始行号，用于定位，不作为剧目身份。
- `source_synced_at`：最后一次从飞书成功同步时间。

保留现有自增 `drama_number` 和稳定内部 `id`。所有工单、排期、运营包、YouTube 视频继续关联内部 `id`。

### 复用现有关系

- `drama_translations` 只表示该剧的目标语言剧名、翻译状态和语言素材状态。
- `youtube_videos` 用于统计剧目已经发布到哪些频道、对应 Video ID、发布时间和发布状态。
- 本阶段不新增制剧进度表。网盘下载、统一参数、字幕提取、鬼手上传、角色提取、制作完成将在第二阶段建立一套剧目级进度表。

## API

新增接口：

- `GET /api/v3/dramas/library`：分页、搜索和筛选剧库，返回总数及汇总字段。
- `GET /api/v3/dramas/{drama_id}`：返回主档、别名、核心词、语言覆盖和频道发布分布。
- `PATCH /api/v3/dramas/{drama_id}`：编辑剧名、网盘链接、内容字段、到期时间、批次和状态。
- `POST /api/v3/dramas/bulk`：批量新增。接收结构化行，逐行返回成功或冲突原因；同一请求不允许产生重复剧名。
- `POST /api/v3/feishu-sync/dramas`：同步实时解析到的飞书“剧库表”。

保留现有 `GET /api/v3/dramas` 给排期等既有选择器使用，避免一次改动破坏生产流程。新页面使用分页接口。

## 页面

### 剧库总表

首屏直接进入可操作表格，不做营销式页面。顶部包含：

- 总剧目、启用、即将到期、归档数量。
- 搜索、状态、批次、到期范围筛选。
- “同步飞书”“新增剧目”“批量录入”三个命令。

每行展示：序号、剧名与剧库编号、批次、到期时间、内容概述、语言覆盖、已发布频道数、状态和详情入口。列表分页，避免当前 327 条数据一次渲染。

### 剧目详情

详情使用三个标签：

1. **基本资料**：编辑九个主档字段、别名和核心词。
2. **语言覆盖**：按当前 `languages` 动态展示，不预造 20 条空业务记录；系统尚未配置语言时明确显示空状态。
3. **频道分布**：按频道展示频道名、Video ID、视频标题、发布时间和发布状态。

### 新增与批量录入

- 单条新增使用完整表单。
- 批量录入支持 CSV 文件，字段与剧库主档一致；服务端使用结构化 CSV 解析，不处理 Excel 样式。
- 批量结果展示新增、更新、冲突和失败行号，不静默跳过。

## 归档规则

- 不提供物理删除按钮。
- `expired` 表示资源到期，`blocked` 表示禁止继续使用，`archived` 表示已下架或飞书“已删”。
- 新建排期和工单只能选择 `active` 剧目。
- 历史排期、运营包和 YouTube 视频仍可查看归档剧目。

## 错误处理

- 飞书缺作品名称：整次同步失败并指出源行号。
- 同一飞书表出现重复规范化剧名：整次同步失败，禁止自动合并。
- 日期无法解析：该行视为错误，整次同步回滚。
- 编辑剧名与其他主剧名或别名冲突：返回 409。
- 批量 CSV 缺必要列：请求失败并列出缺失列。

## 测试与验收

- 单元测试覆盖状态映射、日期解析、标题解析、同步新增、同步更新和内容一致跳过。
- MySQL 集成测试覆盖分页、编辑、归档、批量录入、语言汇总和频道分布。
- 前端契约测试覆盖分页筛选、三个详情标签和操作入口。
- 使用开发 MySQL 实际同步当前 327 条飞书数据，读回总数、抽样字段、归档 30 条和原有 YouTube 关联数量。
- 同步和开发验证均不写生产数据库；生产迁移与数据同步需后续单独授权。

## 本阶段不做

- 智核制剧进度同步。
- 剧目级生产节点和状态历史。
- 20 种语言的人工猜测或预填；等待正式语言清单。
- YouTube 自动上传、自动下架或自动删除。
- 物理删除剧目及关联历史。
