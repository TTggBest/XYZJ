# 智矩账号、租户与设备体系设计

## 1. 目标

在不中断现有线上生产的前提下，为智矩管理系统建立可用于未来收费模式的账号、租户、权限和设备体系，并在该基础上实现频道多选、批量操作和受控删除。

首期登录方式只支持账号密码，不开发短信验证码、邮箱验证码、Google 登录或其他单点登录。

## 2. 核心定义

### 2.1 超级管理员与超级代码机

- 用户是平台唯一超级管理员。
- 用户当前代码机登记为超级代码机。
- 只有“超级管理员账号 + 超级代码机”同时成立时，才具有完整平台权限。
- 普通账号在超级代码机上登录不会自动获得超级权限。
- 超级管理员在非超级代码机登录时，可以进行常规业务管理，但不能执行环境切换、迁移、设备绑定、超管变更等平台高危操作。
- 超级管理员可以创建、停用和切换主账号。切换是改变当前租户上下文，不是伪装成该租户用户。
- 页面顶部必须始终显示“超级管理员模式 · 当前管理：XX 公司”。

### 2.2 主账号与子账号

- 主账号在数据层称为租户 `Tenant`，代表公司、客户和未来的计费归属单位。
- 子账号在数据层称为用户 `User`，代表具体登录人。
- 创建主账号时，管理界面在同一步创建一名“主账号所有者”用户，但数据库中公司与登录人必须是两个独立实体。
- 一个主账号必须且只能有一名所有者；管理员、运营人员和只读人员均为可选子账号。
- 超级管理员不属于任何主账号，通过明确的租户切换上下文管理各主账号。
- 现有 `GoogleAccount` 只代表 YouTube OAuth 授权账号，不复用为智矩登录用户或主账号。

## 3. 角色和权限

系统固定提供五种基础角色：

1. 超级管理员
2. 主账号所有者
3. 主账号管理员
4. 运营人员
5. 只读人员

主账号所有者与主账号管理员的边界：

- 两者都可以管理本租户的频道、剧库、排期、工单、运营包、素材和普通子账号。
- 只有所有者可以修改公司主体资料、申请注销主账号、转让所有权、指定主账号管理员和永久清除频道数据。
- 管理员不能修改、停用或降权所有者。

权限不保存为一段可随意解析的文本，而使用稳定权限码，至少包括：

- `tenant.read` / `tenant.manage`
- `user.read` / `user.manage`
- `channel.read` / `channel.manage` / `channel.delete`
- `schedule.manage`
- `workorder.manage`
- `package.manage`
- `media.manage`
- `youtube.sync`
- `audit.read`
- `platform.tenant.manage`
- `platform.device.manage`
- `platform.environment.manage`

未来的收费套餐使用独立的 entitlement/额度层表示“该租户购买了什么”，不与 RBAC 中“该用户可以做什么”混在一起。首期只保留 `plan_code` 扩展位，不开发支付系统。

## 4. 数据模型

### 4.1 新增核心表

#### `tenants`

- `id`：系统生成的稳定主账号 ID
- `company_name`：公司全称
- `short_name`：主账号切换和列表中使用
- `status`：`active` / `suspended`
- `lease_expires_at`：租约到期时间
- `plan_code`：未来收费套餐扩展位
- `contact_name` / `contact_phone` / `remark`
- `created_by_user_id` / `created_at` / `updated_at`
- `suspended_at` / `suspended_reason`

“已到期”是 `status=active` 但 `lease_expires_at <= now` 的计算结果，不单独保存为可与时间矛盾的人工状态。

#### `app_users`

- `id`
- `display_name`：用户姓名
- `login_name`：当前主要使用手机号，但不限定字段语义为手机号
- `password_hash`：Argon2id 密码摘要，不存明文和可解密密码
- `platform_role`：`super_admin` 或空
- `status`：`active` / `suspended`
- `lease_expires_at`：可空；为空时继承主账号租约
- `password_changed_at` / `last_login_at`
- `failed_login_count` / `locked_until`
- `created_by_user_id` / `created_at` / `updated_at`
- `suspended_at` / `suspended_reason`

#### `tenant_memberships`

- `id`
- `tenant_id`
- `user_id`
- `role_code`：`owner` / `admin` / `operator` / `viewer`
- `status`：`active` / `suspended`
- `created_by_user_id` / `created_at` / `updated_at`

每个租户只允许一条有效 `owner` 成员关系。

#### `permissions` 与 `role_permissions`

- `permissions` 保存稳定权限码和中文名称。
- `role_permissions` 保存五种基础角色与权限的关系。
- 首期不开放自定义角色和单用户权限覆盖，减少难以审计的例外。

#### `auth_sessions`

- `id` / `user_id` / `tenant_id` / `device_id`
- `token_digest`：仅保存高熵会话令牌摘要
- `status`：`active` / `revoked` / `expired`
- `expires_at` / `last_seen_at` / `revoked_at` / `revoke_reason`
- `created_at`

#### `device_user_bindings`

- `id` / `device_id` / `user_id` / `tenant_id`
- `is_default`：该设备默认账号
- `auto_login_enabled`
- `credential_digest`：数据库只存设备秘密摘要，原始秘密存目标 macOS Keychain
- `expires_at` / `last_used_at`
- `bound_by_user_id` / `bound_at`
- `status`：`active` / `suspended` / `revoked`
- `revoked_at` / `revoke_reason`

#### `auth_events`

记录登录成功与失败、退出、会话撤销、密码修改、用户停用、租户切换、设备绑定和解除。不记录密码、会话令牌或设备秘密。

### 4.2 现有 `devices` 扩展

现有 `device_role=builder/studio/worker` 继续表示运行职责。新增的设备信任等级表示安全等级，两者不能混为一个字段：

- `trust_level`：`super_code_machine` / `code_machine` / `production_device` / `normal`
- `status`：沿用 `active` / `inactive` / `retired`
- `last_seen_at`：沿用

IP、hostname、`device_key` 和 `device_role` 只用于识别和运行配置，不能作为登录凭证。

## 5. 登录、免登录与退出

### 5.1 账号密码登录

1. 用户输入 `login_name + password`。
2. 后端校验用户状态、用户锁定时间、所属租户状态和两级租约。
3. 验证成功后创建服务端会话，浏览器只保存 `HttpOnly` Cookie。
4. 生产 HTTPS 下 Cookie 启用 `Secure` 和 `SameSite`；写请求校验 Origin/CSRF。
5. 连续失败达到限制后临时锁定账号，但不向未登录请求泄露“账号不存在”还是“密码错误”。

### 5.2 指定设备免登录

- 对用户可见的登录方式仍然只有账号密码。
- 超级管理员只能在超级代码机上将指定用户、租户和设备绑定，并为现有线上设备设定默认登录用户。
- 原始设备秘密只保存在目标设备 Keychain，用于换取短期服务端会话。
- 设备绑定、用户、租户或租约任一失效时，免登录立即失效。

### 5.3 退出登录

- 右上角账号菜单提供“退出登录”。
- 退出时后端撤销当前会话，清除 Cookie，写入 `auth_events`，返回账号密码登录页。
- 对免登录设备，退出后设置“等待一次人工登录”状态，防止页面立即自动登回。用户下次用账号密码成功登录后，恢复已授权的免登录。
- “解除设备绑定”是独立管理动作，会永久撤销该设备的免登录资格。
- 超级管理员可以强制撤销指定用户的所有会话。用户停用、租约到期和密码重置同样撤销已有会话。

## 6. 租户数据隔离

采用共享 MySQL + 全租户业务表显式 `tenant_id` 方案。不接受只在 `channels` 或少数根表上加 `tenant_id` 后靠人工 join 过滤的方案。

### 6.1 请求上下文

- 认证层先使用独立会话查询确定 `user_id + device_id + tenant_id + role`。
- 业务 API 使用请求级 `TenantSession`，由后端固定 `tenant_id`。
- 普通业务 API 不接受前端 body/query 中的 `tenant_id` 作为授权来源。
- 超级管理员也必须先明确切换当前租户，不允许普通业务查询关闭租户过滤。
- 真正的跨租户平台统计使用独立 `/platform/*` 依赖和 repository，并强制审计。

### 6.2 ORM 和数据库约束

- 所有租户数据模型继承 `TenantOwnedMixin`，`tenant_id` 最终为 `NOT NULL`。
- SQLAlchemy 在 `do_orm_execute` 中对租户模型的 SELECT/UPDATE/DELETE 统一注入租户条件。
- `before_flush` 为新记录写入租户，并拒绝与父对象租户不一致的关联。
- 业务服务通过 tenant repository 取数；跨租户 ID 在详情和写入接口统一表现为 404，不泄露对方存在。
- 高价值父子关系使用 `(tenant_id, id)` 唯一键和 `(tenant_id, parent_id)` 复合外键，防止应用程序错误写出跨租户关联。

### 6.3 租户数据范围

业务租户数据至少包括：

- 频道、YouTube/Google 授权、频道档案、DNA、关键词、分析和品牌素材
- 剧库、翻译、制剧状态
- 批次、飞书同步、任务、工单、运营包、生产节点和所有运营包输出
- 排期、播放列表、社群档位
- 素材、图片处理、Logo 成品和文件路径
- YouTube 视频、评论、播放列表关系、指标、同步水位和配额日志
- 租户级第三方集成、凭证引用、设置、审计和系统事件

平台共享数据可包括语言字典、通用档期模板、平台技能版本、设备目录和运行包构建记录。

### 6.4 文件、后台任务与实时消息

- 文件键统一以 `tenants/<tenant_id>/...` 开头。
- 文件读取、下载和打开所在文件夹之前，必须先通过租户实体查询。
- 飞书、YouTube、图片、生产节点等后台任务必须持久化 `tenant_id`，执行时恢复对应租户上下文。
- SSE 事件必须带 `tenant_id` 并按租户分流；内部事件发布使用服务身份，不再开放无认证发布。

## 7. 审计记录

所有业务写操作和平台管理操作统一记录：

- `tenant_id`（平台操作可空）
- `actor_user_id`
- `actor_device_id`
- `request_id`
- `action`
- `target_type` / `target_id`
- 脱敏变更摘要、原因、结果和发生时间

超级管理员切换租户后执行的业务操作，仍记录真实超级管理员身份与当前作用租户，不记为该租户所有者。

## 8. 频道多选与批量操作

- 频道表格左侧增加行选择框，表头为当前页全选且支持半选状态。
- 翻页时保留已明确选择的频道 ID；筛选改变时清理选择并明确提示。
- 首期只支持对明确的 `channel_ids` 执行批量动作，不将表头全选解释为“选择全数据库”。
- 选中后显示固定批量操作栏：已选数量、启用、停用、同步视频、删除选中、取消选择。
- YouTube OAuth 重新授权仍是单频道动作。Logo 素材首期不做批量覆盖。
- 频道列表升级为服务端分页、搜索和筛选，默认每页 50 条。
- 批量 API 必须在任何写入前，按当前 `tenant_id` 和权限重新查询全部 ID。混入跨租户或不可见 ID 时整批拒绝。

## 9. 频道删除生命周期

界面将三个动作明确分开：

1. **停用**：频道状态改为 paused，阻止新任务和同步，数据完整保留，可恢复。
2. **移入回收站**：频道从普通业务界面消失，取消在途任务，撤销频道授权绑定，但本地数据和文件只读保留 30 天。恢复后进入 paused，不自动复活旧任务和授权。
3. **永久清除**：仅主账号所有者或超级管理员可以从回收站发起。删除智矩数据库中的频道业务子树和精确登记的托管文件，保留最小 tombstone、审计、授权事件和配额记录。

永久清除不调用 YouTube 删除接口，不删除远程频道、视频、播放列表或评论，也不删除可能被其他频道共享的 Google OAuth grant/token。

清除前必须提供预检摘要：关联数据数量、文件数与大小、在途任务、授权状态、飞书权威源仍存在告警。飞书仍有该频道时，保留 tombstone 防止同步重建。

## 10. API 边界

### 10.1 公开接口

仅保留：

- 静态登录页所需资源
- 登录、免登录换会话和最小健康检查

### 10.2 认证接口

- `POST /api/v3/auth/login`
- `POST /api/v3/auth/logout`
- `GET /api/v3/auth/me`
- `POST /api/v3/auth/switch-tenant`（超级管理员）
- `POST /api/v3/auth/revoke-sessions`

### 10.3 平台接口

使用 `/api/v3/platform/*`，同时校验超级管理员和超级代码机：

- 主账号创建、停用、租约和所有者管理
- 设备绑定、默认登录和撤销
- 环境切换、迁移、运行包和平台级配置

### 10.4 业务接口

全部业务接口使用 `current_principal + TenantSession + require_permission`。业务路由不得继续直接依赖无租户 `get_db`。

频道批量操作使用单一批量请求，不由浏览器循环调用单频道写接口：

```http
POST /api/v3/channels/bulk-actions
```

```json
{
  "channel_ids": ["channel-1", "channel-2"],
  "action": "pause",
  "reason": "暂停运营"
}
```

## 11. 无感迁移与上线顺序

开发全部在 `feature/tenant-auth-system` 独立分支进行，测试通过并获得用户明确授权后才能合并 `dev`。

1. **迁移演练**：在生产快照副本上执行，核对逐表行数、空租户数和父子租户不一致数。
2. **增加身份基础**：新建租户、用户、成员、权限、会话、设备绑定和认证事件表，不立即开启强制登录。
3. **创建默认主账号**：把全部现有线上数据归入一个“智矩现有业务”租户，创建超级管理员和该租户所有者。
4. **回填租户**：业务表先增加可空 `tenant_id`，根表归默认租户，子表通过父关系传播，多父关系逐条验证。
5. **迁移文件键**：复制现有文件到默认租户前缀，更新数据库路径；稳定前不删除旧路径。
6. **改造全业务面**：开启 TenantSession、RBAC、后台任务租户上下文、SSE 分流和文件租户隔离。
7. **预绑定线上设备**：在超级代码机上为现有线上设备配置默认租户、默认用户和免登录凭证。
8. **收紧约束**：确认无空租户和跨租户关联后，将租户字段改为 `NOT NULL` 并加复合外键。
9. **开启强制认证**：先验证所有预绑定设备可无弹窗进入，再将未认证业务 API 关闭。
10. **观察后清理**：稳定后再移除旧文件和迁移期兼容路径。

迁移的核心不变式：

- 上线前后默认租户业务数据数量一致。
- 现有线上设备在切换时不出现登录页。
- 未绑定设备只能看到登录页。
- 任何普通用户都不能读取、写入或通过统计推断其他租户数据。

## 12. 错误处理

- 未登录：401，前端返回登录页。
- 已登录但无权限：403。
- 目标属于其他租户：404，不暴露对方资源存在。
- 租户或用户已到期/停用：撤销会话并返回明确业务错误。
- 批量操作在执行前完成全量授权检查；混入不可见频道时零写入。
- 设备或会话被撤销后，下一次请求立即失效。
- 审计不记录密码、token、Cookie、OAuth 明文或设备秘密。

## 13. 验收与测试

### 13.1 认证与会话

- 正确密码、错误密码、锁定、到期、停用、密码重置和登出。
- 退出后原会话无法重用，免登录不会立即重新登入。
- Cookie 安全属性、Origin/CSRF、会话过期与撤销。

### 13.2 设备

- 只有超级管理员 + 超级代码机可以绑定可信设备。
- hostname、IP、`device_key` 或 `device_role` 改写不能获得身份。
- 设备、绑定、用户和租户任一停用会使已有会话失效。
- 超级权限必须同时满足超级管理员和超级代码机。

### 13.3 租户隔离

- 构建两个租户的同形数据，对每类 list/detail/create/update/delete 做正反 IDOR 矩阵。
- 另一租户 ID 在详情和写入接口统一返回 404。
- 列表、计数、搜索、分页、导出、文件、SSE 和后台任务均不泄露其他租户。
- 跨租户复合外键和多父对象租户不一致在数据库与 ORM 两层失败。

### 13.4 角色权限

- 五种角色的每个权限都有正反例。
- 主账号管理员不能处置所有者、公司主体和永久数据。
- 超级管理员未明确选择租户时，不能执行普通业务查询。

### 13.5 迁移与兼容

- 默认租户迁移前后逐表行数一致，无空 `tenant_id`，无跨租户父子关系。
- 现有线上设备切换后无登录弹窗；未绑定设备只显示登录页。
- 默认租户页面的频道、剧库、排期、工单、运营包和素材统计与迁移前一致。

### 13.6 频道多选与删除

- 单选、多选、当前页全选、半选、翻页保留和筛选重置。
- 混合租户 ID 批量请求零写入。
- 停用、回收站、恢复和永久清除的权限与生命周期。
- 清除一个频道不删除共享 Google OAuth grant，不发起远程 YouTube 删除请求。

## 14. 实施模块和并行边界

基础依赖必须串行完成：

1. **A - Auth/RBAC**：密码、会话、退出、权限码、超级管理员和设备绑定。
2. **B - Tenant Schema**：默认租户、业务表租户字段、迁移和 ORM 强制过滤。

A/B 接口稳定后可分组并行：

3. **C - 业务租户化**：频道、剧库、生产、运营包、素材和 YouTube 业务 repository/API。
4. **D - 前端账号中心**：登录、退出、账号菜单、主账号切换、用户/角色/设备管理。
5. **E - 外部边界**：文件、OAuth、飞书、后台任务、SSE 和凭证租户化。
6. **F - 频道批量操作**：服务端分页、多选、批量启停、回收站和删除预检。

最后由主任务串行完成：

7. **G - 越权矩阵与迁移验收**：双租户 IDOR、全量回归、生产快照演练、设备无感登录验收和最终合并候选。

## 15. 非目标

- 首期不开发支付、订阅扣费、发票或额度计费。
- 首期不开发短信、邮件、OAuth 或 SSO 登录。
- 首期不开放租户自定义角色和单用户权限覆盖。
- 频道永久清除不删除远程 YouTube 内容。
- 不将仓库中历史工作流目录和旧授权目录纳入管理系统的自动删除范围。
