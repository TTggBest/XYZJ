# 频道中枢与版本化运营配置设计

## 背景与目标

当前频道页已经能够展示频道列表，后端也已有频道档案、关键词与标签、置顶评论模板、播放列表、素材资产、分析报告和频道 DNA 版本等基础模型。但点击频道后仍以原始 JSON 展示，不能承担频道初始化、装修维护、运营配置、分析参考和后续排期决策的工作。

本设计将频道详情建设为“频道中枢”。频道中枢不是把剧库绑定到频道；公共剧库仍然独立，频道只在排期、播放列表、工单和运营包等具体业务记录中引用剧目。

完整业务闭环为：

`频道基础信息 → 初始画像/分析 → 频道运营参考 → 排期 → 工单 → 运营包 → 上线数据 → 更新分析与运营参考`

## HERO 范围

- 优先复用现有模型、服务和页面模式，只补真实缺口。
- 不新增哈希、校验链、兼容层、feature flag 或通用权限框架。
- 不为尚未落地的会员体系预建完整角色系统。
- 不建设新的文件存储框架；继续通过现有素材资产 ID 引用资源。
- 不在本阶段实现实际 AI 生成、YouTube 播放列表创建或自动排期。
- 不改变公共剧库与频道排期之间的既有边界。

## 数据来源与同步边界

频道初始资料来自飞书的三个工作表：

- `频道总表`：频道名称、中文含义、频道类型、短剧类型等主档字段。
- `频道信息`：频道地址、标题模板、固定符号、弹框方案、置顶评论、播放列表。
- `频道装修`：频道说明、关键词、标签。

飞书同步继续是飞书到智矩的单向同步。本阶段不回写飞书。频道总表行数多于频道信息和频道装修，不能把总表中的每一行都视作已完成初始化的现役频道；现有频道身份记录是详情页的入口，缺失的配置模块以“待完善”展示。

## 频道详情模块

### 1. 基础信息与装修

展示并维护：

- 不可编辑：频道名、YouTube Channel ID、频道地址。
- 可编辑：中文含义、初始题材、短剧类型、频道说明、频道定位。
- 词条：关键词、标签。
- 生成输入/结果：头像出图词、横幅出图词。
- 当前资源：头像图片、横幅图片。

频道名和地址在智矩中作为已绑定的 YouTube 身份只读。现有频道必须已有 `youtube_channel_id`；“只有名称、中文含义和题材的待开通频道”属于后续独立的申请/筹备流程，不在本阶段改变现有频道身份表的非空约束。

头像和横幅继续使用现有 `media_assets`、`channel_profiles` 和 `channel_branding_assets`。频道业务记录只保存素材 ID，不保存固定资源根目录。当前已有的素材摘要字段保持不变，本阶段不增加新的摘要或资源门禁。

### 2. 频道运营配置

展示并维护：

- 置顶评论目标语言正文和中文参考。
- 标题模板、固定符号、弹框方案。
- 播放列表名称、中文名称、地址、目标语言说明、中文说明和状态。
- 短剧类型。

播放列表继续使用现有 `channel_playlists`。本阶段提供结构化展示和人工编辑，不调用 YouTube API。后续阶段在现有记录上增加“创建到 YouTube”动作；成功后回填外部播放列表 ID 和地址。人工创建的播放列表也可补录地址。

### 3. 分析中心

展示：

- 初始分析和周期分析的版本列表。
- 用户画像、题材评分、关键词评分、策略建议和证据。
- 当前生效的频道 DNA/运营参考版本。

初始分析是基于频道静态信息形成的运营假设，必须标记为 `initial`；基于 YouTube 实际数据的报告标记为 `periodic`。页面不能将二者都表述为真实数据结论。

分析正文和可查询的结构化结论继续存 MySQL：报告摘要、增长/下降原因、主辅内容、风险、建议、画像、评分和证据使用现有分析表。PDF、Word、图表快照等导出附件后续作为 `document` 类型素材保存，报告只关联素材 ID；不在业务表中保存绝对路径。

### 4. 频道运营参考

复用现有 `channel_dna_versions` 作为频道运营参考的版本主体，保留受众、题材、情绪、剧情、角色、冲突、标题、封面、社群和节奏等字段。当前生效版本供后续排期与运营包使用。

后续排期、工单和运营包必须记录实际采用的频道 DNA/运营参考版本 ID，不能仅在执行时读取“最新版本”。这个绑定在对应业务进入开发阶段时添加，本阶段不提前修改全部下游表。

### 5. 处理人与权限

页面预留业务概念但不展示空功能：

- 机器角色。
- 机器锁定列表。
- 人员角色。
- 权限范围。

这些内容等会员体系和真实授权流程确定后单独设计，本阶段不新增角色表、不增加页面门禁。

## 可配置短剧类型

新增设置项 `channel_drama_types`，作为频道短剧类型的可编辑字典，最小字段为：

- `id`
- `code`：稳定编码。
- `name`：显示名称，如男频、女频、AI。
- `description`：业务说明，可空。
- `sort_order`
- `status`：启用或停用。
- 创建和更新时间。

频道继续只保留一个短剧类型。为控制迁移范围，`channels.drama_type` 本阶段改为引用类型编码并由服务校验配置是否启用，不立即改成外键；同步和编辑统一使用配置编码。没有明确多选需求前不增加中间表。

## 模板、规范与 Skill 版本

现有 `skills` 和 `skill_versions` 继续作为规则正文的唯一运行真相：

- 一个 Skill 对应一个稳定模块能力，例如频道说明、关键词标签、头像出图词、横幅出图词、置顶评论、标题模板、弹框方案、初始画像、分析报告和运营参考。
- 每个 Skill 独立递增版本，草稿可编辑，发布版本不可覆盖，升级时创建新版本。
- 中文正文用于审核，原文正文用于正式执行；现有发布状态和当前版本机制继续使用。
- MD 文件只作为导入、导出或人工交付格式，不与数据库形成两个并列真相源。

模块版本独立，例如频道说明 v2、排期 v3、运营包 v5。系统整体 v11 仅表示一次发布组合，后续确有展示或追溯需求时再增加轻量的发布清单，记录系统版本引用了哪些 Skill 版本；本阶段不创建发布编排系统。

AI 生成结果将来必须记录使用的 `skill_version_id`。第一阶段只完善 Skill 管理与频道人工结果，不伪造尚未发生的 AI 生成记录。

## 第一阶段交付范围

### 数据库与后端

1. 新增可编辑的频道短剧类型配置和迁移。
2. 为频道补充中文含义、头像出图词和横幅出图词等当前确实缺失的字段；路径仍通过素材 ID 管理。
3. 扩展频道详情响应，组合基础资料、装修、词条、置顶评论、播放列表、分析摘要和当前 DNA。
4. 提供基础/装修/运营配置的人工编辑接口。
5. 复用现有 Skill 版本接口，不重建模板系统。

### 前端

点击频道进入独立详情工作区，首期分为：

- 基础与装修
- 运营配置
- 分析中心
- 运营参考
- 版本与规则入口

首期支持读取与人工编辑，不显示不可执行的 AI 生成按钮、YouTube 创建按钮或人员分配入口。

## 后续阶段

1. 频道初始化生成：按已发布 Skill 版本生成说明、关键词、标签、出图词、置顶评论、标题模板、弹框方案和三条播放列表草稿。
2. YouTube 播放列表：调用已授权频道 API 创建真实播放列表并回填 ID/地址。
3. 分析生成：区分初始假设报告和真实数据周期报告，产生频道 DNA/运营参考版本。
4. 闭环绑定：排期、工单和运营包记录采用的运营参考版本。
5. 会员与角色：机器角色、机器锁定、人员角色和权限范围。

## 错误处理

- 频道不存在返回 404。
- 修改只读身份字段不提供接口，而不是增加额外拦截层。
- 选择不存在或停用的短剧类型返回 422。
- 素材引用沿用现有频道素材校验。
- 单次编辑在一个数据库事务中提交，失败不保留部分修改。
- 外部 AI、YouTube 和飞书写入均不属于第一阶段，因此不增加相关重试或补偿框架。

## 验收标准

- 频道列表点击后不再显示原始 JSON，而是进入结构化频道详情。
- 频道名、YouTube Channel ID 和频道地址只读；允许编辑中文含义、题材、短剧类型和运营配置。
- 设置页可新增、编辑、排序和停用频道短剧类型；频道编辑只能选择启用项。
- 头像和横幅通过素材 ID 关联，频道业务表不新增固定绝对路径。
- 能查看频道的分析报告版本、报告类型、结构化结论和当前运营参考版本。
- Skill 继续独立版本化，已发布版本不覆盖；频道模块不另建第二套模板表。
- 公共剧库没有新增频道归属关系。
- 不出现尚未可用的 AI、YouTube 播放列表创建或角色权限假入口。
- 仅在独立 feature 分支开发；使用 `zhiju_dev` MySQL 完成迁移和测试，不写生产数据库、不打包、不部署。
