# 智矩接入 V14：第一阶段设计

## 目标与范围

让操作者从智矩已有工单启动 V14 文案生产，由当前 Mac 上的 Codex 执行，配置、输入、进度、断点与完整结果保存到云端智矩。关闭 Codex 聊天窗口不影响执行；本地目录不再是这批新任务的唯一业务状态来源。

用户已明确：现有飞书同步内容、流程、字段映射及“任务／工单”叫法全部保持原样。本次直接消费智矩现有数据，不重做飞书工单生成，不按表名重新连接关系。

先接通 V14。暂不建设多版本管理，不修改 V12/V13/V15，不迁移旧本地批次，不修改当前运营 Skills 的生产配置。

## 方案选择

- 采用：云端智矩管理业务状态，本机固定 V14 执行器领取任务并回传。能够沿用现有工单和运营包，同时满足本机跑、云端存的要求。
- 不采用仅让智矩启动现有批处理脚本：该脚本仍依赖本地批次索引、全局当前批次及飞书回写，无法让智矩成为状态来源。
- 不采用全部搬到云端：不符合当前主机、账号及执行方式要求。

## 入口与执行链

在现有工单详情提供“运行 V14”、运行状态、失败原因与“继续运行”。已有分发入口保持原有语义，不能因接入而重复创建工单或运营包。

启动时从当前公司的工单、剧目、频道及配置生成输入快照，固定本次模型与 V14 规则内容。工单、运营包、运行及各阶段使用真实 ID 关联。后续修改设置只影响新运行；继续任务沿用原快照。

复用现有六个生产节点，映射如下：

| 智矩节点 | V14 工作 |
| --- | --- |
| search | 剧情事实与市场证据 |
| title | 标题、角度及后续包装简报 |
| cover | 封面文案与图片提示词 |
| description | 描述、翻译及播放列表建议 |
| community | 社群文案 |
| merge | 汇总运营包并校验完整性 |

保留完整 V14 阶段 JSON、证据、包装简报及失败记录，不能只提取标题等展示字段后丢弃其余内容。既有运营包输出表继续用于当前页面展示。

第一阶段终点是文本运营包可在智矩查看、审核与继续使用，状态为 `text_ready`。图片生成、归档、Logo 及最终交付沿用现有后续流程；本次不自动调用图片供应商，不自动发布 YouTube 视频。

## 云端和本机职责

云端保存：公司归属、工单与运营包关系、运行输入快照、V14 提示词/规则/结构定义、模型选择、阶段尝试、完整结果、错误和创意历史。文件产物通过现有文件存储记录引用，不把图片二进制写入业务表。

本机保存：执行器程序、运行依赖、Codex 登录凭据、临时文件和缓存。执行器通过出站连接领取当前公司授权的任务，无须向公网开放本机端口。只接受固定 V14 操作及结构化参数，不接收任意远程 shell 指令。

首期仅配置当前主机与一个本地 Codex 账号配置。公司设置保存主机 ID、账号配置引用和默认模型；凭据不上传云端。模型选择以该本机实际可用模型为依据，执行前验证；不可用时明确失败，不能静默换模型。桌面已登录不等于 CLI 已验证可用。

保留公司、主机、账号配置之间的关联，供以后增加绑定；首期不做跨主机调度、账号自动切换或负载均衡。

## 执行、失败与恢复

执行器复用 V14 的阶段顺序、结构定义、内容校验和重试分类，但新任务的阶段输入与恢复依据来自云端，不读取旧 `current_batch.json` 决定执行对象，不触发旧脚本的飞书回写。

云端逐阶段保存成功结果后再进入下一阶段。回传网络失败时重传同一结果，不重新生成已成功内容。内容不合格沿用 V14 初次加两次修复的上限；系统、网络及回传失败不冒充内容失败。

每次领取和阶段回传带运行 ID、阶段及尝试 ID，重复回传不得重复入库，过期执行不得覆盖新结果。同一工单不能并发启动两次。首期主机失联显示中断，不自动把任务转交另一主机；继续前确认旧执行已停止，保留已完成阶段。

创意历史从云端读取，成功接受的内容写回同公司历史，不能继续只扫描本机目录。取消任务阻止后续阶段和旧尝试结果被接受，不删除既有结果。

## 验收与权限边界

1. 定向测试确认现有飞书同步和导入行为未变，现有工单及运营包页面仍可用。
2. 使用模型替身验证六阶段串联、完整 JSON 保存、公司隔离、重复启动/回传及断点继续。
3. 验证账号或模型不可用时的明确提示，以及已完成阶段不被重复生成。
4. 用户选定一个测试工单并授权实际执行后，用当前 Mac 和选定 Codex 模型完成一次真实文本运营包；在智矩可查看结果，重启执行器后仍能从云端恢复。

实际模型调用、生产运行、旧批次迁移、飞书写入、提交合并与部署分别按用户授权执行。本文档不是这些操作的执行记录。
