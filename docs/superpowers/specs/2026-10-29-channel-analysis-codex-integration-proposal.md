# 频道分析接入智矩 Codex 通道：方案草案

状态：只读调研后的接入提案，未实施、未部署、未启动分析。2026-10-29。

## 目标与已核对的现状

在智矩频道详情的“分析中心”启动频道分析，Codex 按现有分析技能执行，报告和生成规范回到智矩。共用智矩现有的 Codex 登录检查、绑定主机、网页执行授权、本机唤起及回传方式；不启动外部旧运营包批次。

本轮完整阅读 xy-yt-report-v2 的 SKILL.md 和 authorization、asset-contract、analysis-rules、output-contract、generation-spec-contract 五份约定。检查了系统内 api/v14.py、services/v14_sessions.py、v14_executor/launcher.py、client.py、codex.py 和频道分析现有模型与接口。

现有频道分析表和页面可保存、展示报告、画像、证据、运营参考；尚没有贯通的自动分析执行流程。现有 V14Run 强制关联工单及运营包，不适合作为频道分析的业务记录。CodexClient 当前只传文本与结构化结果约束，尚未装配分析附件和图片输入。

## 方案选择

采用“独立频道分析任务 + 复用系统现有 Codex 接入通道”。

- 频道分析任务以频道为主体，复用身份、授权和本机组件，不创建单剧工单或运营包。
- 不将分析硬塞入运营包六节点；也不另建一套账号、主机登记和常驻调度系统。
- 原 xy-yt-report-v2 的分析规则、三类输入和三个输出保留；文件路径及令牌读取改为平台适配。

## 页面操作

频道详情 → 分析中心：

1. 展示当前生效资料、最近分析时间、分析类型和数据覆盖。
2. “开始分析”打开本次材料工作区，展示频道初始定位、已有数据、28/90 天窗口、ZIP 与截图清单。
3. 正式分析上传一个最近 28 天 Studio 内容导出 ZIP，以及内容/视频、观众、帖子、已完成 A/B 测试截图。帖子和 A/B 未使用时标记不适用；Studio 不展示的数据卡片标记不可用。
4. 授权有效性、材料、模型、本机组件检查通过后才开始。缺少必要资料时列明缺项，保留工作区，不能假装完成。
5. 展示材料检查、API 获取、数据归一、分析、生成规范、校验与归档进度，以及失败原因和继续入口。
6. 展示三个文件及完整原始快照；建议采用“生成完成待应用 → 应用此版本”的方式，生成成功与正式生效分开。此项为建议，尚未取得用户选择。

## 两条分析路径

### 正式数据分析

使用频道现有有效 YouTube 授权；验证频道 ID、名称和实际所需的 Data/Analytics 读取权限。身份或权限不符时使用智矩现有重新授权入口，不要求每次重新授权。历史名称变动显示差异，不用运营昵称冒充 YouTube 标题，不擅自改频道身份。

已同步、覆盖本次频道和窗口的数据直接复用。启动正式分析明确包含本轮 API 拉取；只补齐缺失/过期数据集，保存采集时间。打开页面不触发采集，缺少数据不访问智核。

以最近完整日结束，取最近 28 天及频道年龄允许的最近 90 天；记录时区、实际截止日和 API 数据延迟，不把部分当前日或不足 90 天当完整区间。观众和流量分布分别取得对应窗口，不能拿 90 天分布冒充 28 天。读取 API 时保存覆盖范围，视频数量限制不能静默变成全频道结论。

数据来源保持原规则：Studio ZIP 提供全内容范围曝光和 CTR；视频页截图提供视频范围卡片；Analytics API 提供趋势与明细；观众截图提供年龄、性别等 Studio 信息；A/B 截图提供观看时长份额；智矩现有视频—剧目关联提供剧情事实。不同口径分别保存。

### 冷启动初诊断

尚未运营的频道，以已确认的初始定位、语言、市场、内容类型、标题格式、播放列表和现有固定资料为输入。不要求它提交不存在的 28 天 ZIP，不编造用户画像和数据表现。产物显著标注“冷启动假设／未经数据验证”。

已运营但采集失败、未授权或没有上传材料，属于待补资料；不能自动降级成冷启动。系统可推荐路径并展示依据，用户确认频道尚未运营后才进入初诊断。

## 智矩和 Codex 的职责

智矩负责频道身份与已有凭据、API 采集、原始文件存储、CSV 解析与确定性计算、材料清单、任务状态、输入快照和结果版本。读取凭据沿用现有服务，不将 OAuth 令牌写进模型提示词。

绑定 Mac 上的 Codex 负责理解截图、结合归一数据和剧情分析、撰写画像/诊断并生成规范。执行器将本次 ZIP 解析结果、截图及必要材料下载到独立运行目录；图片必须作为模型可见的图片附件输入。现有 Codex 调用需补上图片输入装配，不能仅把路径字符串塞进提示词。

本次规则固定 xy-yt-report-v2 及其引用资源的版本快照；冷启动使用单独的初诊断规则。与运营包一样固定主机、模型和账号引用，不静默换模型。共用现有本机组件，新增频道分析的固定任务类型和领取/回传接口；不开放任意命令。

成功阶段保留，网络回传失败只重传，API 单项失败只重试该项。中断继续沿用原输入；用户换素材或周期时创建新版本。取消停止后续阶段，旧任务不能覆盖更新的结果。任务完成后退出，不新增无任务轮询。

## 保存与下游消费

正式分析的三个文件：

1. 频道用户画像与长期经营档案.md（原规则的十节）
2. 频道当前运营诊断与运营包指导.md（七节及 channel_strategy YAML）
3. <频道名>_生成规范.md（唯一的运营包频道执行规范）

冷启动也形成同职责的三份产物，画像与结论明确属于假设。完整分析正文和结构化结果进入现有频道分析、画像、证据及运营参考模块；新任务仅补充运行快照、阶段状态、完整结果与附件关联，文件使用现有存储，不把二进制放进业务表。

云端是平台业务记录的权威；本机按登记频道目录落地三份当前文件，并保留原技能的“分析数据/日期_频道分析V2”结构：API 原始数据、Studio ZIP、截图、归一 JSON、更新前文件、最终文件快照。同日多次运行按运行 ID 区分，不覆盖上一批。

云端应用成功而本地镜像失败时显示镜像待补，不能宣称本地文件已更新；重新导出不重复模型调用。

应用结果时，将七段规范及版本引用提供给现有生产入口；保留说明固定资产、CTA、播放列表和专属标签配置。生成 HASHTAG 表达规则不等于已经配置可用的专属候选白名单。

运营包只能读取已生效的生成规范，按 GLOBAL/TITLE/COVER/DESCRIPTION/HASHTAG/COMMUNITY/PLAYLIST 对应阶段使用；不把完整画像、诊断 YAML 直接拼进每个生产阶段。每个新运营包冻结使用的分析及规范版本，已有运行和成品保留原快照。

## 验收

- 有数据频道：28/90 天、API/ZIP/截图均有来源与口径，能从结论追到原始证据。
- 冷启动：无伪造指标与已验证画像；已运营缺数据不会误判为冷启动。
- Codex 确实看到了截图；A/B 百分比标为观看时长份额，CTR 曝光加权，不把未知当零。
- JSON、诊断 YAML、七段规范通过原有确定性校验，GLOBAL 身份不夹带短期策略或具体剧情。
- 三文件、历史、结构化报告和规范版本对应同一频道、同一任务；确认应用后，新运营包能冻结并读到新规范。
- 重复点击不重复运行，断网重传不重生成；租户隔离、旧结果保护和现有运营包流程通过定向回归。

## 实施顺序与边界

先做材料/任务/存储与平台采集适配，再接入现有本机 Codex 通道和截图输入，然后补齐结果展示、应用及运营包读取，最后分别选择一个正式频道和一个冷启动频道进行真实验收。

本方案不含开启真实分析、同步数据、模型调用、资料覆盖、安装、合并或部署的执行记录；本轮没有进行这些操作。
