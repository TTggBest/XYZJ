# 飞书频道排期同步与频道完整排期表设计

## 背景与目标

当前剧库是全系统共享的公共剧库，剧目本身不能直接绑定频道。频道关系只存在于具体的排期记录中：某个频道在某个档位、某个时间安排某部剧。现阶段已有飞书排期工作簿是排期业务真相源，需要先将其只读同步到智矩；待系统自动排期成熟后，再切换为系统内排期。

本阶段交付两项能力：

1. 从指定飞书工作簿读取“频道目录”和各频道工作表，将现有频道排期幂等同步到智矩开发数据库。
2. 在现有“按日查看”之外，提供“频道完整排期”视图，按频道查看全部历史与未来排期。

## 业务边界

- 公共 `dramas` 剧库不增加频道外键，也不创建“剧目固定属于某频道”的关系。
- `channel_schedule_entries` 是频道与剧目的业务关联点。
- 飞书同步方向固定为飞书到智矩，不提供任何飞书写回。
- 飞书历史排期是既有权威数据，可由专用同步流程导入，不受“制剧九节点全部完成”限制。
- 智矩内人工新建或未来自动生成的排期，继续要求剧目制剧九节点全部完成。
- 本阶段不因飞书的“是否写入任务”字段自动创建智矩任务，只同步并展示该标记。
- 只迁移和写入 `zhiju_dev`；不写生产数据库，不打包，不部署。

## 数据模型

在 `channel_schedule_entries` 上补充飞书来源与视频执行状态：

- `source_type`：`manual`、`feishu`、`system`，既有记录默认 `manual`。
- `source_sheet_id`、`source_row_number`、`source_synced_at`：飞书来源定位与最后同步时间。
- `source_video_id`、`source_video_url`：排期对应的 YouTube 视频。
- `is_uploaded`、`is_published`、`is_task_written`：飞书执行状态。

继续使用现有唯一约束 `(channel_id, publish_date, publish_slot_id)` 作为排期业务唯一性。飞书来源行号仅用于追踪，不能作为唯一键，因为插行会改变行号。

## 时间与档位映射

飞书“档期时间”按北京时间解析，转换为频道当地时间和 UTC 时间后固化到排期记录。根据目录映射得到频道，再以当地日期、当地时间和主档/辅档匹配频道档位。实测飞书历史排期包含当前日更配置中已经停用的档位；若该频道、主辅类型和当地时间没有任何档位，同步在同一事务内创建 `archived` 历史档位供旧排期引用，不改变活动档位和频道当前日更次数。同步日前的历史数据允许同一频道、日期、主辅档和时间重复，每条分别引用归档历史档位；同步当天及未来仍禁止这种重复并整批回滚。

频道排期明细只识别 `剧名`、`videoId`、`链接`、`档期`、`档期时间`、`是否上传`、`是否上线`、`是否写入任务` 八个表头，其他列不参与解析。频道目录表仅用于工作表与智矩频道映射。

专门兼容当前源数据中已确认的一条格式错误：`2026-08-010 12:00` 解释为 `2026-08-10 12:00`，并在同步结果中报告一次修正。其他无法解析的日期、未知频道、未知剧目或无法匹配的档位必须使同步失败并回滚，不能跳过后继续提交。

## 幂等同步

同步一次读取频道目录和全部频道表，在同一数据库事务内解析、校验并 upsert：

- 不存在的频道日期档位：插入排期及主选候选记录。
- 已存在的同一频道日期档位：更新剧目、时间、视频状态和来源字段。
- 内容完全一致：记为跳过，仅可更新同步水位字段。
- 任何一行失败：整次业务变更回滚，并返回可定位的工作表、源行号和原因。

同步结果返回工作表数、读取行数、插入、更新、跳过、修正数与完成时间。服务不调用飞书写接口。

## API 与界面

### 同步 API

新增 `POST /api/v3/feishu-sync/channel-schedules`，使用现有飞书凭据只读工作簿并执行同步。

### 频道完整排期 API

新增分页查询接口，参数包括：

- `channel_id`（必填）
- `query`（剧名、剧目编号、Video ID）
- `sort_order`（默认正序，可选正序/倒序）
- `page`（默认 1）
- `page_size`（50、100、150，默认 50）

响应包含总数、页码、每页数量和排期行。每行提供频道、剧目、北京时间/当地时间、主辅档、视频与三项执行标记、来源、同步时间和现有任务状态。

### 前端

频道排期页面增加：

- “按日查看 / 频道完整排期”切换。
- “同步飞书排期”按钮，明确显示只读同步结果。
- 完整排期视图的频道筛选、搜索、正倒序、50/100/150 分页。
- 表格展示排期时间、主/辅档、剧目、Video ID/链接、已上传、已上线、已写任务、来源、同步时间。

## 验收标准

- 公共剧库模型和页面没有新增频道绑定。
- 专用同步可将当前 30 个频道表、1591 条非空排期落入 `zhiju_dev`，再次同步不重复插入。
- 已确认的异常日期被修正并在结果中计数；其他结构或业务错误整次回滚。
- 频道完整排期可按频道查看全部历史与未来记录，并支持搜索、排序和分页。
- 系统人工新建排期仍受制剧完成门槛约束；飞书导入不创建智矩任务。
- 后端全量测试、前端语法检查、迁移检查、真实页面核验通过。
