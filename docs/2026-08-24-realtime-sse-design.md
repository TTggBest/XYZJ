# 智矩多设备实时状态设计

## 目标

多台设备同时操作工单、任务和运营包时，已打开的页面可以在状态变更后立即读取 MySQL 中的最新数据，不使用定时轮询。

## 数据流

1. 每台设备继续运行本机 Web，端口固定为 `127.0.0.1:19732`。
2. 任何成功的业务写请求完成后，本机后端向 Studio 的智矩 SSE 中心发送一条轻量变更通知。
3. Studio 广播通知；浏览器通过 `EventSource` 接收。
4. 前端不直接使用通知里的业务数据，而是重新请求本机 API，从共用 MySQL 读取最新状态。
5. SSE 断线由浏览器自动重连；重连成功后完整刷新当前页面，不需要持久化消息队列。

## 运行配置

- Studio：运行包按 hostname 从 `devices` 表识别为 `studio`，自动留空 `ZHJ_REALTIME_HUB_URL`，本机直接广播。
- 其他生产设备：运行包自动识别为 `worker`，自动使用 `ZHJ_REALTIME_HUB_URL=http://192.168.8.8:19732`。
- 开发环境：默认使用本机 SSE，不依赖 Studio。

## 边界

- MySQL 是唯一业务事实源，SSE 只传输“数据已变更”。
- 通知不包含完整工单、标题、说明或密钥。
- 通知发送失败不回滚已提交的业务数据；页面重连时会再次从 MySQL 校正。
- 本阶段不引入 Redis、WebSocket 或轮询任务。
